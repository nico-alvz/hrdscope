# FAIR principles in hrdscope

This project follows the FAIR principles for both its software and its derived data, and this page records how each principle is met so that the claim can be checked rather than assumed.

Findable. Every release is archived on Zenodo with a version DOI and a concept DOI (10.5281/zenodo.22827123) that always resolves to the latest version. Machine-readable metadata travel with the code in `CITATION.cff` (Citation File Format), `codemeta.json` (CodeMeta) and `.zenodo.json`, all carrying the author's ORCID, the license and controlled keywords. Derived datasets deposited on Zenodo (label tables, tile embeddings, trained weights) receive their own DOIs and are linked to the software record with "isSupplementTo" relations. Tags in git match the version strings in `pyproject.toml` and in the metadata files.

Accessible. Code, metadata and derived data are retrieved over plain HTTPS from GitHub, Zenodo and Hugging Face without registration, under the MIT license for software and CC BY 4.0 for data records. Primary inputs are not redistributed but their exact provenance is recorded in `data/manifests/` with the archive identifiers (GDC file UUIDs and md5 sums, TCIA PathDB image identifiers and URLs) so that anyone can obtain the same files from the same open archives. Metadata remain available on Zenodo even if a file is ever withdrawn.

Interoperable. Data files use open, language-independent formats: tab-separated text for tables, JSON for reports and predictions, HDF5 for tile embeddings with documented datasets and attributes. Identifiers reuse community standards: TCGA patient barcodes, GDC UUIDs, TCIA subject and image identifiers, ORCID for people, SPDX for the license, GRCh38 coordinates from UCSC for genomic reference data. Column meanings are documented next to the data in `data/labels/README.md` and `docs/DATA.md`.

Reusable. The MIT license permits any reuse, including commercial, and the data records use CC BY 4.0. Every derived artefact states how it was produced: the scar scores cite the three original definitions and their validation against a published table, the manifests carry the query date and the script that regenerates them, the splits carry their random seed, and the benchmark stores hyper-parameters, seeds and out-of-fold predictions alongside the metrics. The full pipeline is reproducible from public sources on one consumer GPU with the commands listed in `README.md`, and continuous integration runs the test suite on every push.
